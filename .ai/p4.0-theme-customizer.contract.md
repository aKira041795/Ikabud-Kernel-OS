# Contract — P4.0 Theme customizer must actually control the theme

**Author:** chair · **Date:** 2026-09-14 · **Delegated to:** Codex Sol (`pi`)

## Objective

Make Akira's theme customizer change what the site renders. Today it is a control surface
connected to nothing: the UI reads a schema, stores values, and **no render path ever consumes
them**. Additionally the schema exposes only **2 of the 21 design tokens** the theme ships.

Two deliverables:
1. **Connect it** — saved customizer values must reach the rendered page.
2. **Deepen it** — expose the theme's existing design tokens (colours, fonts, layout) as controls.

## Note for the implementer

The recurring defect in this programme is **a declaration that does not control what it appears to
control**. This slice exists because the customizer declared a schema, stored values, rendered a
form — and changed nothing. If you find yourself making a surface *look* complete without the
rendered output changing, you have reproduced the defect, not fixed it.
