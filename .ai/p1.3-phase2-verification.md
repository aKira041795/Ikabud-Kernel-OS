## What changed

| File | Change |
|---|---|
| `src/helpers/module-registry.php` | New `moduleActivationState()` — three-valued (`active` / `inactive` / `unresolved`) activation resolution. Fail-safe: unknown tenant, unavailable store, undiscovered module, or exception all return `unresolved` (allow) and log. |
| `kernel/Capabilities/CapabilityBus.php` | New `applyActivationGate()` applied in `call()` and `authorize()`, **separate** from `applyPolicy()`/policy authorization. Refuses resolved-inactive providers with the distinct reason `module_not_activated`; allows + logs `module_activation_unresolved`. `provider_activation` policy input now derived from the same tri-state. |
| `src/helpers/module-manager.php` | `invalidateTenantModuleSettingsCache()` bumps the activation-state memo generation so an activation toggle is observed immediately. |
| `tests/activation_gate_dispatch_test.php` | New: active→allow, inactive→refuse(`module_not_activated`), unresolved→allow, mixed provider skip, `app.log` reason. |

No migration, DDL, schema change, policy-row edit/delete, template change, or `gui-settings` read.
`cms-akira-shell` unchanged and still table-free.
