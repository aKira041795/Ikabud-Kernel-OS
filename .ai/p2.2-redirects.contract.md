# Contract — P2.2 Redirects / URL lifecycle

**Author:** chair · **Date:** 2026-09-13 · **Delegated to:** Codex Sol (`pi`)
**Schema change authorized:** standing decision **B3** (`.ai/standing-authorization-and-decisions.md`)

## Objective

Preserve inbound URLs when a published slug changes. Today a slug change silently 404s every existing
link, with no redirect surface and no provider — `redirect` does not appear in any Akira manifest or
helper.

## What exists vs what must be built

| Layer | State |
|---|---|
| Capabilities | **none** — this slice designs them |
| Table | **none** — authorized to add |
| Routes | **none** |
| Nav | **none** |

Note the opposite shape from P2.1/P2.3: there the capability provider existed and only the surface was
missing. **Here both are missing.** Capabilities are designed first, then routes (module convention).

## Capability design (design these before routes)

Propose and justify in your pre-flight, then implement:

- `akira.redirect.resolve@1` — read: given a path, return the target or nothing
- `akira.redirect.list@1` — read: paginated list for the operator screen
- `akira.redirect.upsert@1` — write: create/update a redirect, idempotent
- `akira.redirect.delete@1` — write: remove a redirect

Write capabilities must be idempotent and must declare `requires_protocol: v2`, following the
navigation module's pattern. Do not invent capability names beyond these without stating why.

## Schema (authorized, and constrained)

New table `cms_akira_redirects` in the **module's own migration set** — never applied by hand to the
live tenant.

Non-negotiable, per **ADR-002** (`docs/architecture/adr-002-tenancy-invariant.md`):

- `tenant_id` `INT UNSIGNED NOT NULL`, and it **leads** every composite unique key
- e.g. `UNIQUE (tenant_id, from_path)` — uniqueness is per-tenant by construction
- `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`
- **MySQL 5.7 compatible**: no CTEs, no window functions, no `JSON_TABLE`, no `CHECK` constraints
- Every read and write filters `tenant_id`, even though the tenant has its own database
- Migration must be idempotent (`CREATE TABLE IF NOT EXISTS`)

Include `to_path`, a status/reason, `created_at`, and whatever the capability needs. Do not add columns
speculatively.

## Mandatory pre-flight — report BEFORE writing code

1. **Declaration test.** New handlers must call their capability via `app()->cap()->call(...)`. Report
   the handler line per route.
2. **Policy pre-flight.** New capabilities have **no policy rows yet**. State how the row is created
   for a tenant (the module's seed path) and confirm the seed is narrowing-safe — see
   `CapabilityAuthorizationRegistry::seedPolicy`, which refuses widening. Report what you verified.
3. **Role-set rule.** Any contribution declares the **same role set as the policy row** it points at —
   `admin,administrator,superadmin` unless the row says otherwise. Report which row you checked.
4. **Local-gate check.** Any `*Actor()` / `can*()` guard you write must accept the same role set as the
   policy. Do not write a narrower gate — that has already hidden two features and blocked one build.
5. **Slug-change integration.** State how a slug change *creates* a redirect. If that wiring touches
   another module or the kernel, **stop and report** rather than widening scope.

## Scope

**Allowed:** `modules/cms-akira/cms-akira-navigation/**` or a new redirects module — **justify your
choice**; whichever module owns it, its `routes.php`, `handlers.php`, `helpers.php`, `module.json`,
`database/migrations/**`, `templates/**`, `tests/**`. One sidebar contribution.

**Prohibited:** `kernel/**`, `src/**`; other modules; `composer.json`; editing tests or baselines for a
pass; applying any migration by hand to the live tenant DB.

## Acceptance — evidence per line

1. `php -l` clean on every changed PHP file.
2. Migration present and idempotent; `php ikabud module:validate <module>` passes **with a host
   context** (`HTTP_HOST=akiracms.test`), else it reports false dependency failures.
3. `php _lint_disyl.php <module dir>` passes.
4. Every POST route declared in `capabilities.routes` **and** its handler calls that capability — cite
   handler lines.
5. Page returns **200** authenticated, **303/403** unauthenticated. Show both.
6. Sidebar destinations for `administrator`: **13 → 14**. Show the list.
7. **The redirect actually resolves:** create a redirect through the UI, then request the `from_path`
   and show it redirects (status + `Location`). A screen that stores rows but does not redirect is not
   a redirect feature — this is the acceptance line that matters most.
8. Audit: one non-null-actor row per mutation; duplicate submit idempotent. Show counts.
9. `error.log` gains no product errors. Attribute any line you cause.

## Migration application — important

**Do not apply the migration to the live tenant by hand.** Report the exact command a human should run
(`php ikabud tenant:migrate 54 <module>`), and state clearly that it is **unapplied**. The chair will
authorise its application separately. A migration reaching live data without that step is a process
failure, not a shortcut.

## Cross-cutting rules — do not repeat these

- **Probe the schema; never guess a column.** `SHOW COLUMNS` first. Some tenant tables have **no `id`**
  column (`cms_akira_menus` is keyed by `menu_key`). The chair caused four fatal errors guessing.
- **Clean up after verification** — non-audit rows you create must be removed before you report.
  **Never delete audit rows.**
- `php -l` on `.disyl` is meaningless — use `_lint_disyl.php`.
- `php scripts/run-tests.php <file>` ignores the path, runs the whole suite, unlinks
  `storage/modules.json`, and **truncates `error.log`**. Run individual tests as `php tests/<file>.php`.
- In CLI without a host, `app()->db()` is the **base** DB. Use `dbForTenant(54)`.
- PHPStan needs `-c phpstan.neon`.
- **If a precondition fails: STOP and say which.** Stopping correctly is a successful outcome — it
  already prevented one broken feature this session.
