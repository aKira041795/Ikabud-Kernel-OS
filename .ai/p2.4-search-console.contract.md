# Contract — P2.4 Search operations console

## Objective

Give CMS Akira an operator surface for **search**: run a query, see real indexed results, and rebuild
the index.

`cms-akira-search` already owns `cms_akira_search_documents` and exposes five capabilities —
`akira.search.query@1`, `akira.search.rebuild@1`, `akira.search.upsert@1`, `akira.search.delete@1`,
`akira.search.document.build@1` — but declares **zero** `admin_contributions`. The machinery exists and
is unreachable from the admin. This is the fourth instance of that shape in this programme (theme
customizer, module manager, workflow console).

## Architectural constraints

- The surface reads through `akira.search.query@1` and mutates only through `akira.search.rebuild@1`.
  It must not query the search table directly and must not invent a parallel index model.
- `cms-akira-shell` remains contractually table-free (`owns_tables: []`, `reads_tables: []`). No SQL in
  the shell. All state traverses capabilities.
- Do not add capabilities to `kernel/`. A new capability, if genuinely required, belongs to
  `cms-akira-search`.
- **Declaration test:** every new POST route is declared in `capabilities.routes` **and** its handler
  calls that same capability. A declared route whose handler does not call it fails closed and breaks.
- **Policy pre-flight:** for each capability consumed or declared, confirm in the tenant DB that an
  **active** policy row exists whose `caller_module` permits the calling module and whose
  `allowed_roles` admits `administrator`. Report the row. A missing caller allowlist silently degrades
  (`disabled_caller`) and renders nothing, which looks like "no data".
- **Role-set rule:** any contribution must declare the **same role set as the policy row it points at**.
  Three features have already been hidden by this exact mismatch.
- **Rebuild is a real mutation.** It must be idempotent, governed, and audited. Do not rebuild on GET —
  a page view must never mutate.
- An empty index is a legitimate outcome. Render an explicit empty state and report the real count. A
  query returning nothing is **not** evidence the feature works.
- MySQL 5.7 compatible: no CTEs, no window functions, `ENGINE=InnoDB`.

Binding prohibitions retained as text: no migration, DDL or schema change; no weakening of auth,
authorisation, policy or security; no widening of any role set or policy row; no editing any test,
contract or baseline to obtain a pass; no SQL in `cms-akira-shell`; no new capability in `kernel/`;
no widening scope to meet an acceptance criterion; do not read, copy or link `gui-settings`.

## Acceptance criteria

1. `php -l` clean on every changed PHP file; `php _lint_disyl.php` clean on changed template dirs.
2. `modules/cms-akira/cms-akira-shell/tests/shell_contract_test.php` **still 116/0, exit 0**. Do not edit
   that test.
3. `php ikabud module:validate cms-akira-search` and `... cms-akira-shell` pass.
4. `GET /cms-akira-shell/search` returns **HTTP 200** for the administrator on tenant 54 with a working
   query form.
5. **State the index population honestly.** Report how many documents are actually indexed for tenant 54.
   If the index is empty, say so and show the empty state — do **not** seed documents to make the page
   look populated. If it is empty, rebuild it (that is a legitimate, governed action) and then report the
   resulting count.
6. **Proof a query returns real data:** run a query for a term that exists in tenant 54's content and
   paste the rendered results. If nothing matches, say so — do not substitute a fabricated result set.
7. **Proof rebuild acts:** show the document count before, the rebuild response, and the count after,
   read back from the store. If the count does not change, say so plainly.
8. Idempotency: two identical rebuilds with the same idempotency key do not double-apply.
9. Unauthorized role refused fail-closed — demonstrate with a real request.
10. `storage/logs/error.log` unchanged; no `disabled_caller` authorization failures for the new paths.
11. Report residue: documents, policy rows, audit entries created; what was cleaned and what retained.

## Risks

- **Seeded data masquerading as function.** The index being empty is likely. Seeding documents to make
  the page look populated would be the defect this programme has now found nine times.
- **GET-side mutation.** Rebuilding on page load would mutate on every view. Rebuild must be an explicit,
  audited POST.
- **Silent capability denial.** Check `app.log` for `capability.authz.decision` with `allowed:false`; a
  denied nested capability renders nothing and looks like "no results".
- **Duplicate index sources.** `akira.search.upsert@1` and `document.build@1` exist — reuse them rather
  than writing a second indexing path.
- **Live-tenant damage.** Tests must never bind to tenant 54; use a synthetic tenant.
