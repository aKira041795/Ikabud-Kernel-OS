# Contract — P2.2a Post-path redirects

## Objective

Give CMS Akira governed **redirect management for post paths** — the URL-lifecycle feature a production
CMS needs, so a moved or retired post can send visitors and search engines somewhere sensible instead of
a bare 404.

**Scope is deliberately narrow.** An earlier plan for arbitrary-path redirects was stopped because its
premise was false: **post slugs are immutable** in this codebase, so "old slug → new slug" redirects have
no cause to exist. What *does* exist is the module-level 404 interception point: `cms-akira-shell`
already has `akiraPublicNotFound()`, which is where a post-path redirect belongs.

Do **not** build a global-404 rewrite. Global 404 interception has the highest blast radius in the
system and is explicitly out of scope.

## Architectural constraints

- Redirect resolution must happen at the **module-level not-found seam** (`akiraPublicNotFound()`), not
  in `public/index.php` and not in a kernel request hook. There is no `kernel.request.before_dispatch`
  hook in this codebase — do not invent one.
- Storage is tenant-scoped. The table must carry `tenant_id`, `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci`, and follow the composite-unique-key convention
  (`UNIQUE (tenant_id, …)`) used by every other Akira table.
- Resolution must be **exact-match and single-hop**. No chains, no loops, no regex, no wildcards in v1.
  A redirect row that points at another redirect row must not be followed.
- Only **internal, same-origin** targets. Reject absolute URLs, protocol-relative URLs, and anything with
  a scheme (`javascript:`, `data:`, `//evil`). An open redirect is a security defect, not a feature.
- Redirects must be idempotent and audited. A booking/mutation failure must not leave a half-written row.
- The write surface is administrator-tier only and fail-closed.
- `cms-akira-shell` remains table-free — but note this slice may legitimately need a module-owned
  capability in `cms-akira-core` to read/write the redirect table, since the shell must not own SQL.
- MySQL 5.7 compatible: no CTEs, no window functions, `ENGINE=InnoDB`.

Binding prohibitions retained as text: no weakening of auth, authorisation, policy or security; no
widening of any role set or policy row; no open redirect of any kind (no absolute, scheme-qualified, or
protocol-relative targets); no editing any test, contract or baseline to obtain a pass; no SQL in
`cms-akira-shell`; no new capability in `kernel/`; no global-404 interception; no redirect chains; no
widening scope to meet an acceptance criterion; do not read, copy or link `gui-settings`.

**If a required path is not listed below, REPORT it rather than silently expanding scope.**

## Acceptance criteria

1. `php -l` clean on every changed PHP file; `php _lint_disyl.php` clean on changed template dirs.
2. **Migration is idempotent** — `CREATE TABLE IF NOT EXISTS`, correct charset/engine, `tenant_id`
   present, composite unique key. **Do not apply it to the live tenant by hand**; report the command to
   run (`php ikabud tenant:migrate 54 cms-akira-core`) and state whether you ran it. If you ran it,
   say so.
3. `modules/cms-akira/cms-akira-shell/tests/shell_contract_test.php` **still 116/0, exit 0**. Do not edit
   that test.
4. `GET /cms-akira-shell/redirects` returns **HTTP 200** for the administrator on tenant 54, listing real
   rows **read from the store**, with an explicit empty state if none exist.
5. **State the population honestly** — report how many redirect rows exist before your work. Do not
   fabricate rows.
6. **Proof a redirect acts:** create one redirect through the console, then request the *source* path
   anonymously and show the **real HTTP response** (status + `Location` header). A stored row is not
   evidence; the anonymous response is.
7. **Proof the open-redirect guard works:** attempt to save a redirect whose target is absolute
   (`https://example.com`), protocol-relative (`//evil.test`), or scheme-qualified (`javascript:alert(1)`)
   and show each is **refused**. This is the security acceptance — do not skip it.
8. **Proof the 404 path is otherwise unchanged:** an unknown path that has no redirect row still returns
   the previous 404 response. Show the before/after status and body shape.
9. Idempotency: two identical writes with the same idempotency key do not create two rows.
10. Unauthorized role refused fail-closed — demonstrate with a real request.
11. `composer test` → report all three numbers (passed / failed / skipped). **Zero failures.**
12. `storage/logs/error.log` unchanged by verification.
13. Report residue: rows, policy rows, audit entries; what was cleaned and what retained.

## Risks

- **Open redirect.** The highest-severity risk in this slice. Accepting an absolute or scheme-qualified
  target turns the whole domain into a phishing hop. Acceptance 7 is non-optional.
- **Global 404 blast radius.** Intercepting every unknown path would affect the entry shell, the kernel
  host and public routes at once. Stay inside `akiraPublicNotFound()`.
- **Redirect chains.** A→B→C invites loops and unbounded work. Single-hop, exact match only.
- **Slug premise.** Do not build old-slug→new-slug migration: slugs are immutable here, so there is
  nothing to migrate.
- **Live-tenant schema.** The migration must not be hand-applied to tenant 54 without reporting it.
- **Live-tenant damage.** Tests must never bind to tenant 54.
