# Contract — P5.1 Authority surface (declaration vs policy reconciliation)

**Author:** chair · **Date:** 2026-09-13 · **Delegated to:** Codex Sol (`pi`)

## Objective

Build the operator surface that makes authority legible: what each capability's **effective** policy is,
and where a **declaration disagrees with the policy it points at**.

Both independent reviewers named this the **Akira-required** surface a conventional CMS cannot have, and
this session found **five instances of the same defect** that this screen would have caught by
inspection:

| # | Declaration | Reality |
|---|---|---|
| 1 | `theme:validate` passes | activation rejects the same theme |
| 2 | nav declared `["admin"]` | policy admitted `administrator` → feature invisible |
| 3 | tenant activation declares entitlement | capability dispatch ignored it |
| 4 | `canNavigationActor()` said "Administrator role required" | refused `administrator` |
| 5 | navigation/SEO contributions | had to be hand-checked against policy rows |

**The screen's purpose is to turn that class of defect from a silent condition into a visible one.**

## Verified data (probed by the chair — do not guess columns)

`capability_authorization_policies` (tenant DB), **1514 rows, 51 active**, columns:

```
id · policy_version · capability_id · capability_version · provider · caller_module
allowed_roles · provider_activation_required · requires_protocol · is_active · grant_state
created_at · updated_at
```

Contribution declarations live in each module's `module.json` under `admin_contributions`, plus
`capabilities.routes` for route authority. `akira.policy.list@1` already backs the existing
`/cms-akira-shell/permissions` page — reuse it rather than inventing a capability.

**This slice adds a surface, not a capability.** No schema change. No migration.

## What the surface must show

1. **Effective policy per capability** — the **active** row only (`is_active = 1`), with
   `allowed_roles`, `caller_module`, `grant_state`, `provider`, `requires_protocol`, `policy_version`.
2. **Declaration vs policy delta** — for every sidebar/dashboard contribution that points at a route
   or capability, compare the contribution's declared `roles` against the active policy row's
   `allowed_roles`, and **flag any contribution whose role set is narrower or wider than the policy**.
   This is the check that would have caught defects 2 and 5.
3. **Undeclared routes** — POST routes present in a module's `routes.php` but absent from
   `capabilities.routes`, per module.
4. **Grant state** — surface `granted` / `suspended` / `revoked` distinctly. A revoked or suspended
   grant must be visually unmistakable, never rendered as ordinary.

Read-only. **No mutation in this slice** — no role editing, no grant transitions. Those are separate
contracts with their own audit requirements.

## Mandatory pre-flight — report BEFORE writing code

1. **Declaration test.** New handlers must call their capability via `app()->cap()->call(...)`. Report
   the handler line per route.
2. **Policy pre-flight.** Confirm an **active** policy row exists for every capability you call, with a
   `caller_module` permitting the owning module and `allowed_roles` admitting `administrator`.
3. **Role-set rule.** Any contribution you add must declare the **same role set as the policy row**.
   Verify against the actual row; do not hand-write a guess.
4. **Local-gate check.** Read any `*Actor()` / `can*()` guard you rely on and compare its accepted role
   set with the policy row. Report any mismatch rather than working around it.

## Scope

**Allowed:** the module that owns the new surface (choose the correct owner and justify it in your
report), its `routes.php` / `handlers.php` / `helpers.php` / `module.json`, new `templates/**`, new
`tests/**`, one sidebar contribution.

**Prohibited:** new capability ids · changes to `kernel/**`, `src/**`, other modules · migrations or
schema changes · `composer.json` · editing tests or baselines for a pass · any mutation UI.

## Acceptance — evidence per line

1. `php -l` clean on every changed PHP file.
2. `php ikabud module:validate <module>` passes. **Note:** run it with a host context
   (`HTTP_HOST=akiracms.test`) or it resolves base scope and reports false dependency failures.
3. `php _lint_disyl.php <module dir>` passes.
4. Every POST route declared and called — cite handler lines. (If the surface is read-only, state that
   explicitly and show there are no new POST routes.)
5. Page returns **200** authenticated and **303/403** unauthenticated — show both.
6. Sidebar destinations for `administrator`: **12 → 13**, with the new entry listed. Show the list.
7. **The delta check works:** demonstrate it by showing at least one **real** agreement and, if any
   currently exist, one mismatch found from live data. If none exist, say so explicitly — do not
   fabricate a mismatch to prove the feature.
8. `error.log` gains no product errors. Attribute any line you cause.
9. Residue: state what your verification wrote and its cleanup status. **Do not delete audit rows.**

## Cross-cutting rules — do not repeat these

- **Probe the schema; never guess a column.** Run `SHOW COLUMNS`. The chair caused four fatal errors
  tonight by guessing columns. Some tenant tables have **no `id` column** (e.g. `cms_akira_menus` is
  keyed by `menu_key`).
- **Clean up after verification.** The previous slice left a menu row behind. Remove non-audit rows you
  create; never remove audit rows.
- `php -l` on `.disyl` is meaningless — use `_lint_disyl.php`.
- `php scripts/run-tests.php <file>` ignores the path, runs the whole suite, unlinks
  `storage/modules.json`, and **truncates `error.log`** — beware, it can destroy the evidence you are
  about to cite. Run individual tests as `php tests/<file>.php`.
- In CLI without a host, `app()->db()` is the **base** DB. Use `dbForTenant(54)`.
- PHPStan needs `-c phpstan.neon`.
- **If a precondition fails: STOP and say which.** Stopping correctly is a successful outcome.

## Deliverable

Report: files changed · which module owns the surface and why · pre-flight findings · evidence per
acceptance line · anything unverified · residue status.
