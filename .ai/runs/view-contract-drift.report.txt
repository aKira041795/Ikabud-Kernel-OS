Implementation complete. Here is the evidence report.

## What changed

- **`kernel/Services/ThemeViewContractDrift.php`** (new) — `final` class, one static method `compare(array $declaredViews, array $registeredFields): array`. Pure: no `app()`, container, file I/O or globals. Two distinct reasons: `contract_not_registered` (view has no contract entry; caller warns) and `field_not_in_contract` (contract exists but lacks the declared field; caller errors). Tolerates malformed `fields`. Constants `REASON_CONTRACT_NOT_REGISTERED` / `REASON_FIELD_NOT_IN_CONTRACT`.
- **`modules/cms-akira/cms-akira-theme/helpers.php`** — `catThemeValidate()` now reads `entity-view-map.json`, pulls `app()->entityViews()->registeredViewContracts()`, converts to `"entity.view" => list<string>`, calls `compare()`, appends errors/warnings, and records `checks['entity_view_contract']` (`true`/`false`, or `'skipped'`). When no contract is obtainable (empty contracts, resolver unavailable) it **skips** — no error, no manufactured pass.
- **Three maps corrected** (only `fields`; `actions`, names, composition untouched):
  - `post.list` → `["title","subtitle","image","metadata","categories","actions","url"]`
  - `post.detail` → `["title","subtitle","image","body","metadata","categories","actions","url"]`
  - Files: `akira-editorial`, `akira-ark`, `akira-ark-demo`. `composition.detail` intentionally left as-is → `contract_not_registered` warning.
- **`tests/akira_theme_view_contract_drift_test.php`** (new, pure) — requires the kernel class and `entity-views.php` directly, rebuilds the registered map via a bare `EntityViewResolver`, passes arrays. No `bootstrap.php`, no `MODE_INTEGRATION`.
- **`modules/cms-akira/cms-akira-theme/tests/theme_view_contract_drift_test.php`** (new, wiring) — bootstraps, calls `requireNotLiveTenantDatabase()`, exercises `catThemeValidate()` for clean pass, forced error, and skip.

No field genuinely read by a template is absent from the contract. Templates read `title, subtitle, image, body, metadata, url, categories`; all are registered, so no "finding to report" arose.
