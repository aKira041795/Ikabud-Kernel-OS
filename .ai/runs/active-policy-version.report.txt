# Implementation report — active policy version

## What changed

**Kernel (one additive static method only):**
- `kernel/Capabilities/CapabilityAuthorizationRegistry.php`: added `public static function activePolicyVersionForCurrentScope(): int`. It mirrors `seedPolicyForCurrentScope()` exactly (`AuthorityScopeResolver::forApplication()`, `resolveForCapability([], ['user' => …])`, `database($scope)`), derives the version from `activePolicyRows()`, returns `1` for no app / no scope / no PDO / empty set / any `Throwable`, and never touches an ambient DB. No other kernel file or method was touched.

**Every declaration seed now routes through that one resolver (inline re-derivations removed):**
- `cms-akira-core/helpers.php` — 5 pinned rows, the shell-read inline block, and `cacSeedGovernancePolicies()`.
- `cms-akira-core/helpers.php` — **`cacActivePolicyVersion()` deleted**; governance calls the kernel resolver.
- `cms-akira-shell/helpers.php` — the **literal `30` is gone**, replaced by the resolver.
- `cms-akira-builder`, `cms-akira-navigation`, `cms-akira-search`, `cms-akira-seo`, `cms-akira-theme`, `cms-akira-workflow`, `cms-akira-media`, `gui-settings` — pinned literals and/or inline blocks replaced.
- `cms-akira-media/helpers.php` — `camMediaActivePolicyVersion()` also deleted (second named duplicate).
- `tests/active_policy_version_test.php` — new pure source-level guard (no `require`/`include`, no `bootstrap.php`, no `MODE_INTEGRATION`).

## Reported findings (not silently changed)

1. **Unlisted kernel instance of the same defect class — `kernel/Services/ModuleInstallService.php:78`.** Its default `policySeeder` builds rows with `'policy_version' => 1` and writes them with `new CapabilityAuthorizationRegistry($db)->seedPolicy($rows)`. On a late module install against a tenant whose active version has advanced, those rows land invisible, exactly like `akira.user.revoke_sessions@1` did. The contract forbids me from touching any kernel file other than the additive method, so I did **not** change it and did **not** add it to the guard's scanned list (doing either would violate the contract). This is a real remaining instance of the class and needs a follow-up slice or an explicit scope expansion.

2. **`modules/cms-akira/cms-akira-theme/tests/theme_read_authority_test.php` was edited (reported, not forbidden).** Its `$seedJoinsActiveVersion` check source-inspected the old inline mechanism (`activePolicyRows()` + `$activeRows[0]['policy_version']`). Since the contract requires every declaration seed to use the single kernel resolver, I re-pointed that check at `activePolicyVersionForCurrentScope()`. The guarantee is unchanged (the seed joins the active version, never version 1); it is not weakened or deleted. Without this, the theme test gained one failure.

3. **Pre-existing failure, not introduced here — `tests/gui_settings_route_authority_declaration_test.php` (7 passed, 1 failed).** It asserts the Akira census rollup `dispatch_enforced == total == 47`, but the tree reports `48`. I confirmed by stashing all my changes: the clean `6605efb` tree fails identically with the same 47-vs-48 census value. The same stale-47 expectation also makes the theme test's census assertion fail (the only theme failure left). Both are pre-existing and unrelated to this slice.

## Explicit statements

- **Widening is still refused.** I changed no seed semantics (`seedPolicy()`, `widenedFields()`, `governedFieldsChanged()` untouched). The D-Q4 widening-refusal assertions in `tests/capability_authorization_policy_migration_test.php` still pass (18/0). That is expected, not a defect.
- **Policy rows already seeded at `policy_version = 1` on existing tenants are NOT migrated by this slice.** This change only stops *new* declarations from landing at a pinned version. Existing invisible rows (including, potentially, rows written by `ModuleInstallService`) remain in the database and will still read as `missing_policy_row` until a follow-up migration or re-seed moves them.
