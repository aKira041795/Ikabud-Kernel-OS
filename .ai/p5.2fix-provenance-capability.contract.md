# Contract — P5.2-fix: route the provenance read through a capability

**Author:** chair · **Date:** 2026-09-13 · **Delegated to:** Codex Sol (`pi`)
**Trigger:** `modules/cms-akira/cms-akira-shell/tests/shell_contract_test.php` → `✗ shell is table-free`

## The defect being fixed

P5.2 delivered a working provenance surface but **broke an architectural contract**: the shell now
issues raw SQL against `audit_logs` and `users`, and declared it:

```
modules/cms-akira/cms-akira-shell/helpers.php:1067  SELECT COUNT(*) FROM audit_logs a
modules/cms-akira/cms-akira-shell/helpers.php:1081  SELECT COUNT(*) FROM audit_logs WHERE ...
modules/cms-akira/cms-akira-shell/helpers.php:1084  SELECT DISTINCT module FROM audit_logs ...
modules/cms-akira/cms-akira-shell/helpers.php:1087  SELECT DISTINCT action FROM audit_logs ...
modules/cms-akira/cms-akira-shell/module.json       reads_tables: ["audit_logs","users"]
```

The shell is contractually **table-free** (`owns_tables: []`, `reads_tables: []`). The test is correct
and must NOT be edited.

## Why the existing capability cannot be used as-is

`kernel.audit.list@1` (registered at `kernel/App.php:432`) is **unfit** for this surface:

| Issue | Detail |
|---|---|
| Entity-scoped | Requires `entity_type`; returns `['rows' => []]` without it. A provenance feed needs *all* changes |
| Wrong authorization | Throws unless the caller is kernel `admin`/`superadmin`. The surface's audience is `administrator` — they would be **denied** |
| Lossy actor | It sets `$row['actor'] = 'System'` when unattributed — **exactly the conflation the P5.2 contract forbids** |

So the correct fix is a **new, purpose-built capability**, not raw SQL and not a forced reuse.

## Required change

**1. Register `kernel.provenance.list@1`** in `kernel/App.php`, modelled on
`kernel.audit.list@1` but corrected:

- **Payload:** `{module?: string, action?: string, page?: int, per_page?: int}`
- **Returns:** `{rows: list, total: int, pages: int, page: int, modules: list<string>,
  actions: list<string>, unattributed_count: int}`
- **Authorization:** permit `admin`, `administrator`, `superadmin` with `source === 'kernel'`,
  consistent with the policy convention used elsewhere. Do **not** narrow it to `admin`/`superadmin` —
  that is the defect class this programme has now hit six times.
- **Actor preservation — the critical requirement.** Expose the three-part model verbatim:
  `actor_user_id`, `actor_module_user_id`, `actor_source`. Derive a display `actor` label but **never
  collapse an unattributed row into "System"**: when all three are null, the label must say so and
  carry the `actor_source` value (`cli:unattributed`, `unauthenticated`, or "source missing (legacy)").
  `unattributed_count` must count rows where **both** actor ids are null.
- Use the same `KernelPDO::kernelEscalationEnter/Leave` wrapping as `kernel.audit.list@1`.
- MySQL 5.7 safe: no CTEs, no window functions.
- Bound `per_page` (e.g. 1–100) and compute `pages` from `total`.

**2. Rewire the shell.** `akiraShellProvenanceSnapshot()` must call
`app()->cap()->call('kernel.provenance.list@1', ...)` and perform **no SQL**. It may keep its current
signature and return shape so the template is unaffected, but the `PDO $db` parameter should be dropped
if nothing else uses it.

**3. Restore the manifest.** `modules/cms-akira/cms-akira-shell/module.json` → `reads_tables: []`.
