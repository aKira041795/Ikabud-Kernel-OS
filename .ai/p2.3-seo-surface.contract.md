## Copy the proven pattern

`cms-akira-navigation` P2.1 and `cms-akira-theme` P1 are the working precedents. Mirror them:

| Element | Pattern |
|---|---|
| Admin page | own route, e.g. `/cms-akira-seo` → `akiraSeoAdminPage` |
| Form POSTs | own routes, e.g. `/cms-akira-seo/upsert`, `/cms-akira-seo/delete` |
| Declared authority | **every** POST in `capabilities.routes` mapped to its capability |
| Sidebar entry | `admin_contributions`, `host: cms-akira-shell`, `location: sidebar` |
| Templates | module-owned `.disyl` |

## Mandatory pre-flight — report findings BEFORE writing code

1. **Declaration test.** You are writing new handlers, so satisfy it **by construction**: every POST
   handler MUST call its capability via `app()->cap()->call(...)`, and only then may the route be
   declared. Report the handler line for each route.
2. **Policy pre-flight.** For each capability you declare, confirm in the tenant DB that an **active**
   policy row exists with a `caller_module` that permits the owning module and an `allowed_roles` set
   that admits `administrator`. `caller_module = NULL` is treated as unrestricted. Report the row.
3. **Role-set rule.** Any contribution must declare **the same role set as the policy row it points
   at**. Do not hand-write a guess — two features were already hidden by exactly this mistake.
4. **Local-gate check.** Read any `*Actor()` / `can*()` guard in this module and compare its accepted
   role set with the policy row. Three guards so far were **narrower than the policy behind them**,
   one with an error message that contradicted its own check. If this module has one, align it and
   report the before/after.

## Cross-cutting rules learned the hard way — do not repeat these

- **Probe the schema; never guess a column.** Run `SHOW COLUMNS`. The chair caused four new fatal
  errors tonight by guessing `id`/`name` on a table keyed by `menu_key`, and `body`/`context_json`
  on others. There is no penalty for running `SHOW COLUMNS`; there is for guessing.
- **Clean up after verification.** The previous slice left a menu row in live tenant data. Any row
  your verification writes must be removed before you report. **Do not delete audit rows** — removing
  provenance is tampering; report what you left.
- `php -l` on a `.disyl` file is **meaningless** (parsed as inline HTML). Use `php _lint_disyl.php <dir>`.
- `php scripts/run-tests.php <file>` **ignores the path**, runs the whole suite, unlinks
  `storage/modules.json`, and can poison web APCu (503 on the live tenant). Run individual tests as
  `php tests/<file>.php` with `> file 2>&1` and read `$?`.
- In CLI without a host, `app()->db()` resolves the **base** database. Use `dbForTenant(54)`.
- PHPStan needs `-c phpstan.neon`; a bare file path ignores the repo config.
- **If a precondition fails: STOP and say which.** Do not widen scope to reach the acceptance criteria.
  Stopping correctly is a successful outcome; the previous slice did exactly that and it was the most
  valuable thing it did.
