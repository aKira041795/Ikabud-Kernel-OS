SLICE G — the missing authority route for existing test files (CD-22's exceptions: block)
implementation report · status: COMPLETE · authority: CD-44 (owner: "lift the freeze. fix")

Summary
An `exceptions:` block is parsed from the task contract into the normalized record; it is bound into
the contract revision id; it is guarded against the verifier trust surface and forbidden_scope; and
the existing-test prohibition consults it as a route. The prohibition itself is unchanged and stays
absolute: without a matching pre-declared exception the verdict is byte-for-byte the old one
(ESCALATE / L4 / exit 3). The route is visible and attributed: the check verdict names the exception
and its authority, and the run record carries both the declared exception (at start) and the
authorised exception (at finish).

Non-vacuity — what fails when each fix is reverted
1. Matching exception -> RECORD (test 51). Revert the `existing_test` dismissal in commandCheck(): the
   absolute branch fires again, test 51 fails on verdict RECORD, and the route is gone.
2. No exception -> ESCALATE / L4 / exit 3 (test 52). Revert nothing here; this is the load-bearing
   control. If the dismissal were applied to every absolute matcher (or to paths with no matching
   exception), test 52 fails (exit 0 where 3 is required) and test 58 fails (a gate-config change
   would record). It is the assertion that stops the route becoming the default.
3. Trust-surface exception -> refused (tests 53, 53a). Remove exceptionPolicyViolations() from plan/
   check: the exception is accepted, test 53/53a fail (exit 0 instead of 2), and the exception becomes
   the rule-1 bypass.
4. After-dispatch exception -> no effect (test 57). Remove `exceptionDecidedBeforeDispatch()` (or the
   `--dispatch-at` pass-through in scopeConformance): test 57 fails (exit 0 instead of 3) and an
   exemption shaped to fit a red result is honoured.
5. Structural validation (tests 54, 55, 56). Remove parseExceptions()'s field validation: test 56
   fails (exit 0 / no "missing required field"); remove parseExceptionScope()'s normalizePath call:
   test 55 fails; remove the forbidden_scope guard: test 54 fails.
6. Record naming (ai-run test 50). Remove `declared_exceptions`/`authorised_exceptions` recording:
   test 50 fails on the record assertions, and an authorised change becomes invisible.
7. Pre-declaration binding (ai-run test 52). Remove exceptions from revisionId(): the retrofitted
   exception no longer moves the revision, test 52 fails (exit 0 instead of 3).
8. Additive format (test 59). If exceptions were always included in revisionId(), the plain and
   empty-block revisions would differ and test 59 fails; AC2's byte-identity claim would be false.
