CLAIM: argvForCommand() generalises without loosening — the executable comes from the matched rule
COMMAND: sed -n '/^function argvForCommand/,/^}/p' tools/ai-run.php
OBSERVED:
function argvForCommand(string $command): ?array
{
    $rule = matchingAllowlistRule($command);
    $exec = $rule === null ? null : ($rule['exec'] ?? null);
    if (!is_string($exec) || $exec === '') {
        return null;
    }
    // The anchored pattern guarantees the first token is this rule's fixed executable word; it is
    // dropped and the rule's `exec` is substituted, so the command text can never choose the binary.
    $parts = preg_split('/\s+/', trim($command)) ?: [];
    array_shift($parts);
    array_unshift($parts, $exec);
    return array_values(array_filter($parts, static fn (string $part): bool => $part !== ''));
}
(exit 0)

Non-vacuity of the generalisation: commandIsAllowlisted() and argvForCommand() now read the SAME
verdict from the SAME single table interpreter (matchingAllowlistRule()). There is no code path in
which a command is permitted but argv[0] is taken from the command text: argv[0] is always $exec from
the rule, and $argv is null whenever the rule is null (so nothing is executed). The command text only
supplies arguments after its first token is discarded. Reverting this generalisation to the old
`str_starts_with($command, 'php ')` makes test 26a and 26c fail because the Python shapes no longer
reach execution.

Other architectural constraints
================================================================================
- Timeout: the new shapes run through the same executeArgv() call as the PHP shapes, so they use the
  verify command's single `--timeout` bound (default 120s). No shape has a weaker or absent bound.
- No new runtime dependency: PHP stdlib only, Python stdlib only; the tool remains zero-dependency and
  still requires only DevelopmentTaskContract.php.
- PHP 8.3-compatible: the new code uses only `str_contains`, `preg_split`, `getenv`, `array_merge`,
  `str_replace` and `proc_open` with `bypass_shell`; no 8.4+/8.5-only syntax.
- Exit codes unchanged: 0/2/3/4 are untouched; verify still returns EXIT_GATE only on CONTRADICTED.
- Refusing `..`, `;`, `&&`, `|`, backticks and `$(…)`: `..` is refused globally in
  matchingAllowlistRule(); the other operators are refused because every pattern is anchored `^…$`, and
  the command is executed as an argv array with `bypass_shell => true`, so no shell is ever involved.
