# Contract — P5.2 Provenance surface

**Author:** chair · **Date:** 2026-09-13 · **Delegated to:** Codex Sol (`pi`)

## Objective

Make per-change provenance operator-visible: **who made this change, under which capability, and how
the actor was identified.** Both independent reviewers named this (with P5.1) as the surface a
conventional CMS cannot offer, because mainstream CMSs cannot answer *"who authorised this"* from the
server.

Phase 0 found the reason this matters concretely: **7 of 132 audit rows were wholly anonymous**
(`akira.post.publish` among them), and the chair fixed the writer so it can no longer happen. This
surface is where an operator verifies that claim for themselves.

## Verified data (probed by the chair — do not guess columns)

`audit_logs` in the tenant DB, **134 rows**, columns:

```
id · module · actor_user_id · actor_module_user_id · actor_source · branch_id
action · entity_type · entity_id · old_data · new_data · metadata_json · created_at
```

Note the **three-part actor model**, which is the point of this surface:

| Column | Meaning |
|---|---|
| `actor_user_id` | kernel user id — set only when `source = 'kernel'` |
| `actor_module_user_id` | module-owned user id — set when the actor is a module user |
| `actor_source` | how the actor was identified: `kernel`, `cli:admin`, `cli:unattributed`, `unauthenticated` |

Post revisions also exist (`cms_akira_post_revisions`) and may be referenced, but this slice is about
the audit trail.

**Read-only. No schema change. No new capability** — `akira.post.admin.list@1` and the existing shell
read patterns show the way; reuse what exists rather than inventing a capability.

## What the surface must show

1. **A chronological change list** — action, module, entity, timestamp, and the **rendered actor**.
2. **Actor rendering that distinguishes the three cases**, never collapsing them:
   - kernel user → username
   - module user → source label + module user id
   - **unattributed** → shown explicitly as *unattributed*, with its `actor_source`
     (`cli:unattributed` / `unauthenticated`) — **never silently rendered as "System"**. That
     conflation is exactly what hid the defect.
3. **Filtering** by module and by action at minimum.
4. **A visible count of unattributed rows** on the page. If the number is non-zero, an operator should
   see it without querying the database. This is the check that would have surfaced the Phase 0 finding.
5. **Per-row detail** — the capability/action and the entity it touched.

## Mandatory pre-flight — report BEFORE writing code

1. **Declaration test.** New handlers call their capability via `app()->cap()->call(...)`. Cite the
   handler line.
2. **Policy pre-flight.** Confirm an **active** policy row exists for any capability you call, with a
   `caller_module` permitting the module and `allowed_roles` admitting `administrator`. Report the row.
3. **Role-set rule.** Any contribution declares the **same role set as the policy row** it points at.
   Report which row you checked.
4. **Local-gate check.** Any guard you write accepts the same role set as the policy. **Do not write a
   narrower gate** — that has hidden two features and blocked one build already.

## Scope

**Allowed:** the owning module's `routes.php`, `handlers.php`, `helpers.php`, `module.json`, new
`templates/**`, new `tests/**`. One sidebar contribution. (`cms-akira-shell` is the natural owner, as
P5.1 — justify it.)

**Prohibited:** `kernel/**`; `src/**`; other modules; migrations or schema changes; `composer.json`;
editing tests or baselines for a pass; any write or mutation UI.

## Acceptance — evidence per line

1. `php -l` clean on every changed PHP file.
2. `php ikabud module:validate <module>` passes **with a host context** (`HTTP_HOST=akiracms.test`) —
   without it, it resolves base scope and reports false dependency failures.
3. `php _lint_disyl.php <module dir>` passes.
4. POST routes declared and called if any exist; if the surface is read-only, **state that explicitly**
   and show there are no new POST routes.
5. Page returns **200** authenticated, **303/403** unauthenticated. Show both.
6. Sidebar destinations for `administrator`: **13 → 14**. Show the list.
7. **The surface tells the truth about unattributed rows:** show the rendered count, and show at least
   one row rendered by each actor case that exists in live data (`kernel`, and any `cli:*` /
   `unauthenticated` rows present). If a case has no live row, say so — **do not fabricate one.**
8. `error.log` gains no product errors. Attribute any line you cause.
9. Residue: state what your verification wrote and its cleanup status. **Never delete audit rows.**

## Cross-cutting rules — do not repeat these

- **Probe the schema; never guess a column.** `SHOW COLUMNS` first. Some tenant tables have **no `id`**
  (`cms_akira_menus` is keyed by `menu_key`). The chair caused four fatal errors guessing.
- **Clean up** non-audit rows you create before reporting.
- `php -l` on `.disyl` is meaningless — use `_lint_disyl.php`.
- `php scripts/run-tests.php <file>` ignores the path, runs the whole suite, unlinks
  `storage/modules.json`, and **truncates `error.log`** — it can destroy the evidence you cite. Run
  individual tests as `php tests/<file>.php`.
- In CLI without a host, `app()->db()` is the **base** DB. Use `dbForTenant(54)`.
- PHPStan needs `-c phpstan.neon`.
- **If a precondition fails: STOP and say which.** Stopping correctly prevented a broken feature twice
  this session — it is a successful outcome.

## Deliverable

Report: files changed · ownership decision and why · pre-flight findings · evidence per acceptance line
· anything unverified · residue status.
